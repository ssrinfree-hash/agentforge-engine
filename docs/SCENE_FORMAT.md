# AgentForge — формат сцены (.afscene)

Сцена движка AgentForge — JSON-файл (обычно с расширением `.afscene`), дерево
нод в стиле Godot: корень → дети → внуки. Формат self-describing: движок сам
умеет его сохранять (`scene.save`) и загружать (`scene.load`, а также флаг
`--scene` и инлайн-объект в команде `scene.load`). Версия движка **0.1.0**,
формат сцены — `version: 1`.

## 1. Общая структура

```json
{
  "format": "agentforge-scene",
  "version": 1,
  "time": 0,
  "scores": {},
  "root": {"type": "SceneTree", "name": "root", "children": []}
}
```

- `format` — всегда `"agentforge-scene"`.
- `version` — всегда `1`.
- `time` — время симуляции в секундах на момент сохранения (при загрузке
  восстанавливается).
- `scores` — объект «число: число» — игровое состояние (score, hp, ...).
- `root` — корневая нода. Тип корня — всегда `"SceneTree"`, имя — всегда
  `"root"`; при загрузке эта нода не создаётся заново, а совпадает с корнем
  дерева (движок распознаёт её по типу/имени).
- Каждая нода: `type` (один из шести), `name` (уникально среди детей родителя),
  опционально `props` (объект свойств) и опционально `children` (массив нод).

## 2. Правила имён и путей

- Имя ноды уникально **среди детей одного родителя**. Дубликат → ошибка загрузки
  `duplicate child name '<имя>' under '<родитель>'`.
- Символ `/` в имени ноды использовать нельзя — это разделитель путей.
- Путь ноды — цепочка имён через `/`: `Arena/Crate/Lid`. В ответах движка и
  отчётах путь пишется с корнем: `root/Arena/Crate`.
- Animator ищет цель `target_path` **среди своих детей** (относительный путь;
  пустая строка — анимируется родитель Animator'а). Шаблон: Animator в корне,
  анимируемый объект — его ребёнок, `target_path` = имя объекта.

## 3. Сахар-поля

Свойства можно писать двумя способами — они эквивалентны:

```json
{"type": "MeshInstance3D", "name": "Crate", "props": {"position": [0, 0.5, 0]}}
```

```json
{"type": "MeshInstance3D", "name": "Crate", "position": [0, 0.5, 0]}
```

- **Внутри `props`** можно указывать любое свойство ноды (см. типы ниже).
- **На верхнем уровне ноды** (сахар) при загрузке из файла применяются только
  пять ключей: `position`, `scale`, `rotation_euler_deg`, `color`, `visible`.
  Команда `node.add` по протоколу принимает на верхнем уровне шире: ещё
  `body`, `static_body`, `mesh_class`, `velocity` (см. `docs/AGENT_PROTOCOL.md`).
  Надёжный вариант — всегда писать всё внутри `props`.
- Порядок применения: `props` — в алфавитном порядке ключей, затем сахар.
  Поэтому если задать оба поворота (`rotation_euler_deg` и
  `rotation_quat_xyzw`), применён будет **кватернион** (он идёт позже по
  алфавиту) — это осознанное поведение: кватернион точнее.

### Повороты

- `rotation_euler_deg` — углы Эйлера **в градусах**, порядок осей XYZ;
  применение: сначала Z, потом X, потом Y (`R = Ry·Rx·Rz`). Пример:
  `[-18, 0, 0]` — наклон вниз на 18°.
- `rotation_quat_xyzw` — кватернион `[x, y, z, w]` (единичный — `[0, 0, 0, 1]`).
- Внутренне движок хранит поворот кватернионом; `scene.save` пишет именно
  `rotation_quat_xyzw` (без euler-версии).

## 4. Типы нод

### Node

Логический контейнер (группировка детей). Свойства:

| поле | тип | умолч. | описание |
|---|---|---|---|
| `name` | string | — | имя; при пустом движок подставит `Node<id>` |
| `enabled` | bool | `true` | `false` — нода и её дети исключаются из рендера/физики |
| `type` | string | — | всегда `"Node"` |

### Node3D

Node + трансформ в 3D (позиция/поворот/масштаб, иерархия трансформов:
мировая матрица = родитель × локальная). Дополнительные свойства: `position`
`[x,y,z]` (умолч. `[0,0,0]`), `rotation_euler_deg` `[3]` (градусы), 
`rotation_quat_xyzw` `[4]`, `scale` `[x,y,z]` (умолч. `[1,1,1]`).

### MeshInstance3D

Node3D + геометрия и материал. Свойства:

| поле | тип | умолч. | описание |
|---|---|---|---|
| `mesh` | object | — | mesh-спека (раздел 5); в 0.1.0 из **файла** игнорируется, применяется через `node.add`/`node.set` |
| `color` | `[r,g,b]` | `[0.8,0.8,0.8]` | базовый цвет (умножается на цвет меша из OBJ MTL Kd) |
| `visible` | bool | `true` | скрытые ноды не рендерятся и не участвуют в raycast |
| `static_body` | bool | `false` | неподвижный коллайдер для физики |
| `body` | bool | `false` | динамическое тело: гравитация, коллизии, события |
| `velocity` | `[x,y,z]` | `[0,0,0]` | начальная скорость динамического тела |
| `mesh_class` | string | `""` | семантическая метка ("crate", "coin"...), попадает в FrameReport (`class`) |

Служебные поля в ответах/сохранениях (только чтение, при загрузке
игнорируются): `mesh_name` (имя меша), `mesh_tris` (число треугольников).

### Camera3D

Node3D + параметры камеры. Смотрит вдоль локального −Z, «верх» — +Y.

| поле | тип | умолч. | описание |
|---|---|---|---|
| `fov_deg` | число | `60` | вертикальный угол обзора в градусах |
| `near_z` | число | `0.05` | ближняя плоскость отсечения |
| `far_z` | число | `200` | дальняя плоскость отсечения |
| `active` | bool | `true` | кадр рендерится с первой активной камеры |

### Light3D

Node3D + направленный свет (один на сцену; берётся первая активная). Направление
луча — вдоль локального −Z (задаётся поворотом ноды), «падающий сверху» свет —
отрицательный угол вокруг X, например `[-55, -30, 0]`.

| поле | тип | умолч. | описание |
|---|---|---|---|
| `color` | `[r,g,b]` | `[1,1,1]` | цвет света |
| `intensity` | число | `1.0` | сила (умножается на цвет) |
| `active` | bool | `true` | используется ли свет |

### Animator

Node3D + keyframe-трек на трансформ другой 3D-ноды. Движок проигрывает трек
каждый шаг `sim.step` (линейная интерполяция pos/scale, slerp для кватернионов).

| поле | тип | умолч. | описание |
|---|---|---|---|
| `target_path` | string | `""` | путь цели **среди детей Animator'а**; пусто — анимируется родитель Animator'а |
| `keyframes` | массив | — | трек; при загрузке из него вычисляется `length`; в сохранённой сцене заменён числом `keyframes` (см. ниже) |
| `playing` | bool | `true` | проигрывать ли |
| `loop` | bool | `true` | зацикливать ли по достижении `length` |
| `anim_class` | string | `""` | метка ("spin", "bob"...) для отчётов |
| `length` | число | `0` | длина трека в секундах; вычисляется как max(t) из keyframes |

Кадр трека:

```json
{"t": 0.5, "pos": [0, 1, -4], "rot_quat_xyzw": [0, 0.3827, 0, 0.9239], "scale": [1, 1, 1]}
```

- `t` — время в секундах от начала трека; кадры должны идти по возрастанию t.
- `pos` — позиция цели в момент t; `rot_quat_xyzw` — поворот `[x,y,z,w]`;
  `scale` — масштаб цели. Пропущенные поля берутся нулевыми/единичными.
- В **сохранённой движком** сцене вместо массива `keyframes` пишется число
  `keyframes: <кол-во>` (трек не сериализуется) — восстановление трека
  возможно только повторной установкой массива. В **рукописной/бридж-сцене**
  пиши массив `keyframes` — движок его принимает.
- `time` — служебное поле (текущая позиция проигрывания), при загрузке
  игнорируется.

## 5. Mesh-спецификация

Поле `mesh` ноды `MeshInstance3D` — объект с одним из двух вариантов:

**Примитив** (`primitive`, размерные поля опциональны):

| primitive | поля | умолчания | геометрия |
|---|---|---|---|
| `box` | `size: [x,y,z]` | `[1,1,1]` | полный размер по осям, центр в origin |
| `plane` | `size: [s]` | `10` | квадрат в плоскости XZ со стороной s, нормаль +Y |
| `sphere` | `radius` | `0.5` | UV-сфера |
| `capsule` | `radius`, `height` | `0.5`, `1.8` | цилиндр + полусферы по вертикали Y |

```json
{"primitive": "box", "size": [1, 1, 1]}
```

**Файл** (`file` — путь к ассету относительно рабочего каталога afengine):

```json
{"file": "assets/chair_0001.obj"}
```

- Поддерживаются **OBJ** (цвет материала берётся из MTL-файла, строка `Kd`) и
  **OFF** (ModelNet40; нормали вычисляются по граням).
- Меши кэшируются по пути — несколько нод могут делить один файл.
- Если `color` ноды задан, он умножается на цвет меша.

## 6. Пример полной сцены

Камера, свет, статичный бокс, динамичная сфера и аниматор (монета, ребёнок
Animator'а). JSON валиден и принимается `scene.load`.

```json
{
  "format": "agentforge-scene",
  "version": 1,
  "time": 0,
  "scores": {"hp": 3, "score": 0},
  "root": {
    "type": "SceneTree",
    "name": "root",
    "children": [
      {
        "type": "MeshInstance3D",
        "name": "Ground",
        "props": {
          "mesh": {"primitive": "plane", "size": [40]},
          "position": [0, 0, 0],
          "rotation_euler_deg": [0, 0, 0],
          "scale": [1, 1, 1],
          "color": [0.25, 0.5, 0.25],
          "visible": true,
          "static_body": true,
          "mesh_class": "floor"
        }
      },
      {
        "type": "MeshInstance3D",
        "name": "Crate",
        "props": {
          "mesh": {"primitive": "box", "size": [1, 1, 1]},
          "position": [0, 0.5, -3],
          "color": [0.8, 0.4, 0.1],
          "visible": true,
          "static_body": true,
          "mesh_class": "crate"
        }
      },
      {
        "type": "MeshInstance3D",
        "name": "Ball",
        "props": {
          "mesh": {"primitive": "sphere", "radius": 0.4},
          "position": [2, 3, -1],
          "color": [0.9, 0.9, 0.2],
          "visible": true,
          "body": true,
          "velocity": [0, 0, 0],
          "mesh_class": "ball"
        }
      },
      {
        "type": "Animator",
        "name": "Spin",
        "props": {
          "target_path": "Coin",
          "playing": true,
          "loop": true,
          "anim_class": "spin",
          "keyframes": [
            {"t": 0, "pos": [0, 1, -4], "rot_quat_xyzw": [0, 0, 0, 1], "scale": [1, 1, 1]},
            {"t": 1, "pos": [0, 1, -4], "rot_quat_xyzw": [0, 0.7071, 0, 0.7071], "scale": [1, 1, 1]}
          ]
        },
        "children": [
          {
            "type": "MeshInstance3D",
            "name": "Coin",
            "props": {
              "mesh": {"primitive": "box", "size": [0.5, 0.5, 0.05]},
              "position": [0, 1, -4],
              "color": [1, 0.85, 0.1],
              "visible": true,
              "mesh_class": "coin"
            }
          }
        ]
      },
      {
        "type": "Camera3D",
        "name": "Cam",
        "props": {
          "position": [0, 2.5, 6],
          "rotation_euler_deg": [-18, 0, 0],
          "fov_deg": 60,
          "near_z": 0.05,
          "far_z": 200,
          "active": true
        }
      },
      {
        "type": "Light3D",
        "name": "Sun",
        "props": {
          "rotation_euler_deg": [-55, -30, 0],
          "color": [1, 1, 1],
          "intensity": 1.2,
          "active": true
        }
      }
    ]
  }
}
```

Загрузка: `{"cmd":"scene.load","path":"arena.afscene"}` (запускать afengine из
каталога, где лежат файл сцены и `assets/`, — пути к мешам относительные).
Сфера с `body:true` упадёт на землю при первом `sim.step` и породит событие
`ground_hit`; монета будет вращаться Animator'ом `Spin` (цикл 1 с, поворот на
90°).

## 7. Особенности версии 0.1.0

- `scene.load` из файла применяет `props` нод и сахар
  (`position`, `scale`, `rotation_euler_deg`, `color`, `visible`); поле `mesh`
  у нод из файла **игнорируется** — геометрию прикрепляй командами
  `node.add`/`node.set` (спека та же). Сцена с заданными `mesh`-полями
  загрузится без ошибок, но меши будут пустыми, пока их не прикрепить.
- Повороты при сохранении пишутся только как `rotation_quat_xyzw`;
  `rotation_euler_deg` — форма записи для рукописных сцен и `node.add`.
- `scene.save` сериализует трек Animator числом `keyframes: <N>` (массив не
  сохраняется) — см. раздел 4.
- Иерархия трансформов поддерживается: вложенные Node3D передают
  позицию/поворот/масштаб детям (мировая матрица = родитель × локальная).
